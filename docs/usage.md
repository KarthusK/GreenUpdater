# GreenUpdater 使用指南

> 面向使用者的操作手册。架构与需求细节见 [`docs/design/`](design/README.md)。

GreenUpdater 是一个**纯前台、完全手动**的便携软件更新器：没有后台常驻、没有定时任务、没有系统托盘、没有通知。你打开窗口 → 勾选软件 → 点【检查】/【更新】→ 看结果 → 关掉。所有数据都存在程序自身目录里，整个文件夹拷走即迁移。

## 1. 安装与启动

### 方式 A：绿色版可执行文件（推荐给普通用户）

拿到打包好的 `GreenUpdater.exe`（或整个 `GreenUpdater.dist/` 文件夹）后，双击即可运行，无需安装 Python。首次运行会在 exe 同级目录自动生成数据库、日志、备份、临时目录。

> 想换电脑或做备份：直接把整个文件夹拷走即可，配置和历史都在里面。**唯一例外是 GitHub Token**——它存在系统凭据库里，不随文件夹走，换机后需重新填一次（见[第 6 节](#6-github-token)）。

### 方式 B：从源码运行（开发者）

```bash
# 一键：创建虚拟环境 → editable 安装 → 启动
python run.py

# 或手动
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"      # Windows
# .venv/bin/pip install -e ".[dev]"        # Linux/macOS
.venv/Scripts/python -m greenupdater
```

### 打包成可执行文件

```bash
python build.py            # Nuitka standalone（文件夹，杀软误报少，推荐）
python build.py --onefile  # 单文件（分发方便，误报率略高）
```

产物在 `build/` 下。

```
├──────────────────────────────────────────────────────────────┤

│  ┌──┬──────────┬────────┬────────┬────────────┐              │

│  ├──┼──────────┼────────┼────────┼────────────┤              │
│  │☑ │ LibreWolf │ 130.0  │ 131.0  │ ● 可更新    │              │

```

- **列表与终端之间是可拖动的分隔条**，可上下调整高度。
- **勾选（首列复选框）** 决定【检查】/【更新】作用于哪些行；点表头勾选框 = 全选 / 全不选。默认全部勾选，勾选态不保存，每次启动重新全选。
- **当前行（单击高亮的那一行）** 决定【编辑】/【删除】/【回滚】和右键菜单作用于哪一项。
- 停用的软件（配置里取消「启用」）会灰显、不可勾选、不参与批量。

### 状态含义

| 状态 | 含义 |
| --- | --- |
| 未检查 | 还没跑过检查 |
| 已最新 | 本地版本 = 最新版本 |
| 可更新 | 发现更新版本 |
| 更新中… | 正在执行流水线 |
| 更新成功 | 本次更新完成 |
| 失败(阶段) | 在某阶段失败，如「失败(覆盖)」；鼠标悬停看详细错误 |

## 3. 添加一个软件

点【添加】打开表单，分四个区。带 `*` 为必填。

### 基本信息
- **名称**：列表里显示的名字，随意起。
- **仓库**：只填一个框，程序会自动识别成 `owner/repo`。可以直接粘贴 GitHub 上【Code】按钮里复制的任意一种克隆地址：
  - HTTPS：`https://github.com/owner/repo.git`
  - SSH：`git@github.com:owner/repo.git`
  - GitHub CLI：`gh repo clone owner/repo`
  - 也可以直接手写 `owner/repo`（如 SumatraPDF 是 `sumatrapdfreader/sumatrapdf`）。

  留空时框内会灰字提示格式。填完点到别处，地址会自动规范化成 `owner/repo`，便于确认识别正确。
- **源类型**：仓库框右侧显示，目前只有 GitHub（其它为预留）。

### 版本匹配（最关键，决定能否挑对文件）
- **资产匹配正则**：用来从 Release 的文件列表里挑出你要的那个压缩包。用正则匹配**文件名**。
  - 例：SumatraPDF 的 64 位 zip 是 `SumatraPDF-3.5.2-64.zip`，正则可写 `SumatraPDF-.*-64\.zip`。
  - 例：LibreWolf 的便携包 `librewolf-131.0-windows-x86_64-portable.zip`，正则可写 `librewolf-.*-windows-x86_64-portable\.zip`。
  - `.` 要转义成 `\.`；不确定就先写宽一点，命中多个时程序会让你手选（见下）。
- **版本来源**：
  - `tag`：版本号取自 Release 的 tag（如 `v3.5.2`）。
  - `资产文件名`：版本号从匹配到的文件名里取。
- **版本提取正则**：从 tag 或文件名里抠出纯版本号，需含**一个捕获组**。留空则用整体。
  - 例：文件名 `SumatraPDF-3.5.2-64.zip`，提取正则 `(\d+\.\d+\.\d+)` → 得到 `3.5.2`。
- **包含预发布版本**：勾上则连 prerelease 一起考虑；默认只看正式版。

> 匹配到多个资产时，程序会先按架构关键字（`x86_64`/`x64`/`win64`/`64bit`/`amd64`）过滤；若仍多于一个，会弹出**多资产选择框**让你手动挑。

### 安装位置
- **目标目录**：软件所在的本地文件夹（就是解压覆盖的目的地）。用【浏览…】选。
- **可执行文件相对路径**：主程序 exe 相对目标目录的路径，如 `SumatraPDF.exe` 或 `app\foo.exe`。用于探测本地版本和确认进程归属。
- **本地当前版本**：可点【探测版本】从 exe 的 PE 版本资源自动读取（仅 Windows）；读不到就手填。留空表示「未安装」，下次更新按全新下载处理。旁边的标签显示来源（PE自动 / 手填 / 未知）。

### 更新行为
- **进程名列表**：更新前需要结束的进程名（如 `librewolf.exe`），可加多个。程序会同时校验进程 exe 是否真的在目标目录下，避免误杀同名进程。
- **排除路径(保留)**：覆盖时**跳过**、回滚时**保留**的相对路径，用来护住你的配置/数据（如 `Profiles`、`config`、`data`）。
- **更新前备份(完整快照)**：默认开启。关闭时弹警告——关掉后覆盖阶段失败将**无法回滚**，目标目录可能损坏。
- **启用**：取消勾选则该软件整体停用、灰显、不参与批量检查/更新。

填完点【确定】。校验不通过（正则非法、必填为空等）会弹提示。

## 4. 检查与更新

- **检查**：只读，拉取最新 Release、算出最新版本、更新状态列，不改动任何文件。作用于**勾选行**。
- **更新**：对**勾选行**逐个（顺序执行，不并行）跑完整流水线：

```
检查 → 下载到临时目录 → 解压到临时目录 → [运行中?结束进程] → [开启备份?做完整快照] → 覆盖目标目录
```

过程中：
- **进度条**独立显示当前项进度；**终端面板**输出离散日志行。
- 目标程序在运行 → 弹**结束进程确认框**：「结束并继续」或「取消」（取消则该项中止，不算失败）。
- 命中多个资产 → 弹**多资产选择框**，单选后继续；取消则该项记为 `失败(check)`。
- 点【取消】→ 协作式停止：当前项处理到安全点后退出，剩余项不再处理，临时文件清理。
- 全部跑完 → 状态栏与终端汇总「K 成功 / J 失败（/ N 取消）」。

> 下载 / 解压都在**临时目录**进行，这两步失败**不会动**你的目标目录，也就无需回滚。只有**覆盖阶段**改动了原文件，失败才可能需要回滚。

## 5. 回滚

- **何时可用**：仅当某项在**覆盖阶段失败**且当时**存在快照**时，该行标记为「可回滚」，右键菜单「回滚到此版本」和工具栏【回滚】才可用。
- **回滚行为**：用更新前的**完整快照**还原程序文件，但**跳过排除路径**——也就是说你的配置 / 用户数据保持当前状态，不会被回退。
- 回滚成功后，该项状态更新为「更新成功（已回滚）」，历史里对应记录标记为已回滚。
- **失败不会自动回滚**，一律由你手动触发。

## 6. GitHub Token

不填 Token 也能用，但走**匿名访问**，GitHub 限流约 **60 次/小时**，软件多了容易触顶。填 Token 可提高到约 5000 次/小时。

**如何创建**：GitHub → Settings → Developer settings → Personal access tokens → 生成一个**只读 public 仓库**即可的 token（更新公开软件不需要任何写权限）。

**在 GreenUpdater 里**：设置 → GitHub → 粘贴 Token → 【保存】。

> ⚠️ **Token 存在系统凭据库**（Windows 凭据管理器 / Linux Secret Service），**不进**数据库、**不进**导入导出的 JSON、**不随**便携文件夹携带。这是有意的安全设计：换机器需重新填一次。
>
> 若当前系统**没有可用凭据库**，Token 输入框会禁用并显示红字提示，程序自动降级为匿名访问。

【清除】按钮可随时删掉已保存的 Token。

## 7. 设置

设置 → 各分区，点【确定】保存（Token 的保存/清除是即时生效的独立按钮）。

- **网络**：勾选「启用代理」并填代理 URL（如 `http://127.0.0.1:7890`）。改动后程序会重建网络组件使其生效。
- **日志**：级别 `DEBUG/INFO/WARNING/ERROR`，改动即时生效；【打开日志目录】直达日志文件夹。
- **默认项**：「新增软件默认包含预发布」——影响之后新建的软件条目默认值。
- **便携目录（只读）**：展示数据库 / 备份 / 临时目录的实际位置，每项带【打开】按钮。

---

## 8. 导入 / 导出

- **导出**：把所有软件配置 + 本地版本 + 设置写成一份 JSON。**不含 Token、不含更新历史**。
- **导入**：从 JSON 恢复；按 uid 去重（已存在则更新，不存在则新增），完成后汇总「新增 / 更新 / 错误」。

适合在多台机器间同步配置，或做配置备份。

---

## 9. 更新历史

右键某项 → 「查看更新历史…」，只读表格列出每次尝试：时间、从哪个版本、到哪个版本、结果、失败阶段、是否已回滚。鼠标悬停可看错误详情。

## 10. 便携与数据目录

所有可变数据都在程序目录（exe 旁 / 开发态项目根）内：

| 内容 | 位置 |
| --- | --- |
| 配置 + 历史数据库 | `greenupdater.db` |
| 日志 | `logs/greenupdater.log`（轮转，单文件 5MB，保留 5 份） |
| 完整快照备份 | `backups/<软件uid>/` |
| 下载 / 解压临时区 | `tmp/<软件uid>/` |

- 备份按软件 **uid** 存放，改名字也不受影响；每个软件**只保留 1 份**最近快照。
- 想指定别的数据根目录：设环境变量 `GREENUPDATER_HOME=<路径>`（便携自定义 / 测试用）。
- 迁移：整目录拷走即可（记得 Token 需重填）。

## 11. 安全说明

- **防 Zip Slip**：解压时校验每个条目路径不得越出目标目录，拦截「路径穿越」恶意压缩包。
- **SHA256 校验**：若 Release 提供了校验值则比对；不一致会失败。缺失时仅警告、不失败。
- **覆盖只增不删**：覆盖阶段只新增 / 覆盖文件，不会删除目标目录里的其它文件。
- **结束进程需确认**：不会静默杀进程；且校验进程 exe 位于目标目录，避免误杀同名进程。
- **最小权限**：Token 只需只读 public 权限；程序不做提权、不改注册表、不设开机自启。

## 12. 常见问题

**Q：状态一直是「未检查」/ 检查报错？**
A：多半是 GitHub 匿名限流（60 次/小时）。填 Token 后重试；或检查代理设置。悬停状态列可看具体错误。

**Q：匹配不到资产 / 命中一堆？**
A：调整「资产匹配正则」。命中多个时程序会先按 64 位架构关键字过滤，仍多个则弹框让你手选。

**Q：本地版本探测不到？**
A：PE 探测仅 Windows、且要求 exe 内含版本资源。读不到就手填版本号。

**Q：更新失败怎么办？**
A：看失败阶段——`下载`/`解压` 阶段失败没动你的文件，重试即可；`覆盖` 阶段失败且该行显示「可回滚」，右键回滚还原程序文件（用户数据保留）。

**Q：关闭「更新前备份」有什么风险？**
A：覆盖阶段一旦失败将**无法回滚**，目标目录可能处于半更新状态。除非磁盘空间紧张，建议保持开启。

**Q：能同时开两个 GreenUpdater 吗？**
A：不能。程序是单实例的，再次启动会激活已有窗口而不是新开一个，避免两个更新流程互相干扰。

**Q：终端面板能清屏吗？**
A：能。终端右上角有【清屏】按钮，点一下清空当前显示。终端只读、累积全部历史并自动滚到底，最多保留 5000 行后自动丢弃最旧的。
